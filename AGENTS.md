- Escale BOUFF (pays du mois) is driven by the database: daily pg_cron job calls public.escale_tick(), which proposes, publishes and removes the single linked menu item (restaurants.escale_menu_item_id) — why: kitchen/admin/client apps need no special code beyond reading the menu.
- Marketing push notifications are decided in the database: hourly pg_cron job calls public.marketing_tick(), every send goes through public.marketing_send() which enforces quiet hours, opt-in, daily/weekly caps and no-active-order — why: one place for all anti-spam rules.
- Counter till (web /caisse) authenticates cashiers by per-person 6-digit PIN checked in the database (counter_login → hashed session token); all counter writes go through counter_* security-definer functions, orders are tagged source='counter' with cashier_id and paid_at — why: cashiers never get admin accounts, every sale is traceable, and cash/MoMo-at-counter can only be marked paid by a valid till session.
- Kitchen new-order alert is sent by DB trigger push_kitchen_new_order() on Android channel 'orders' (custom beep sound, bypass DND) — why: kitchen must ring even when the app is closed; channel/sound changes need a native rebuild.
- Rider app startup steps (fonts, secure storage, mode, auth) must each fail open with catch/timeout, plus an 8 s global fallback — why: any hang showed riders a blank screen with no way out.
- Native maps (client + rider apps) use MapLibre with OpenFreeMap tiles and OSRM public routing (throttled, straight-line fallback); the client app imports maps only via src/bouff/map.js (react-native-maps-compatible shim) — why: no Google billing account available, and one shim keeps all screens provider-independent.
